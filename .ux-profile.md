# UX Profile

Written by hand for Bitwise (not by `setup-ui-ux-skills`). All UI/UX
skills in this project read this file before changing layout, copy, or
interaction, and `ux-audit` scores against it instead of the catalog
defaults.

## Aesthetic reference

- **Standard:** Custom — "Instrument", on a Linear base
- **Notes:** A bench instrument, like an oscilloscope: the circuit and its
  values are the content, the chrome stays quiet and dense around them.
  Three adjectives: dense, exact, quiet.
  - **Identity (fixed):**
    - IBM Plex Sans for all chrome (400, 500 and 600 only).
    - Green-grey neutrals from `src/index.css` (`--surface`, `--border`,
      `--hover`, `--text*`, `--canvas-bg`, `--ink`, `--wire`).
    - Amber (`--accent`, `--accent-soft`) is the only accent: selection,
      hover, focus, the critical path and active toggles.
    - Red, green, blue and the value palette belong to signal values
      (`--signal-*`, `valueStyle.ts`). Never use them for chrome, status
      badges, buttons or decoration.
  - **Density:** High.
    - Rows about 28px and the toolbar about 32px.
    - Panels are tight, with no "card in a card".
    - The canvas gets the space.
  - **Depth:** Built from 1px hairlines in `--border`, and surfaces separate
    by background shift.
    - Docked panels (palette, inspector, timing panel) carry no shadow.
    - Floating layers (dialogs, popovers, toasts, the probe bubble, the
      phone bottom sheet) get exactly one soft shadow plus a border.
  - **Radius:** Small.
    - 3–4px on controls (buttons, inputs, chips, kbd).
    - Up to 6px on panels and floating layers.
    - Nothing above 8px.
    - 999px only for true pill toggles.
  - **Typography:**
    - Sizes come only from the four `--text-*` variables in
      `src/index.css`; never write a pixel size in `App.css`.
    - Every changing number (ticks, values, counts, delays, zoom) uses
      `font-variant-numeric: tabular-nums` so readouts don't jitter.
    - IBM Plex Mono (500 and 600, `--font-mono`) is the face for values:
      the inspector and probe readouts, digits and buses on the canvas
      (`drawValue` in `render.ts`), and the values, ticks and cursor of the
      timing diagram (`VALUE_FONT` in `scopeRender.ts`). Names and labels
      stay in Plex Sans. It falls back to Plex Sans, never to a system
      monospace.
  - **Motion:**
    - 0–140ms, `transform` and `opacity` only, `ease-out` on enter.
    - No decorative motion. The canvas pulse and wave are the one moving
      element allowed, and they stop under `prefers-reduced-motion`.
  - **Interaction grammar:**
    - Keyboard-first: `/` for quick add, Ctrl+K for command search, and Esc
      closes the top layer.
    - Every command with a shortcut shows its `kbd` chip in the command
      search and in tooltips.
    - Shortcuts match on `event.code`.
  - **Tokens:** radii come from `--radius-control` (4px) and
    `--radius-panel` (6px), and the one floating shadow from
    `--shadow-float`, all in `src/index.css`. A primary or destructive
    button is ink on the surface (`.button-main`, `.button-danger`): the
    words name what goes, never a hue. A conflict in the chrome is ink with
    a thick dashed underline, like a conflict on the canvas.

## Banned anti-aesthetics

- Gratuitous glassmorphism (`backdrop-filter` without a hard edge)
- Neon glowing borders / multi-stop rainbow CTAs
- Floating pastel pill badges for ordinary metadata
- Decorative blob / mesh gradients behind content
- Nested scroll regions (page + card + list all scroll)
- Cartoon people waving / high-fiving / celebrating
- Huge centered illustration with no CTA
- Icons inside inputs unless functional (search, clear, password reveal)
- Soft drop-shadows as the only separator (no border)
- Disabled primary submit as the only incomplete-form feedback
- Project-specific bans:
  - A second accent color, or amber used for anything other than
    selection, focus, hover, the critical path or an active state.
  - Signal colors (`--signal-*`, value palette hues) in chrome: buttons,
    badges, headings, icons or toasts.
  - Shadows on docked panels.
  - Gradients anywhere in the chrome. Gradients are allowed only for
    value colors above radix 10, drawn by `valueStyle.ts`.
  - Pixel font sizes in `App.css`, or a fourth font weight.
  - System monospace stacks (`monospace`, `Consolas`, `Courier`) for value
    readouts.
  - Emoji as UI icons.
  - Decorative motion: bouncing, springy overshoot, shimmer, or
    attention-seeking loops.
  - Changing numbers set in proportional figures.

## Accessibility target

- **Level:** WCAG 2.1 AA
- **Contrast:**
  - Text on `--surface` and `--part-fill` must reach 4.5:1, in both light
    and dark themes.
  - `--text-faint` is for disabled and placeholder text only, never for
    content.
  - Signal colors must stay distinguishable without hue: Z is dashed, X is
    dotted, and a conflict is thick and dashed.
- **Touch / focus:**
  - Under a fine pointer, dense targets are allowed, at least 24×24px.
  - Under `pointer: coarse` and at 640px or narrower, targets are at least
    40×40px.
  - Focus is the 2px amber `:focus-visible` outline from `src/index.css`;
    never remove it without a replacement of the same strength.
  - Dialogs trap focus and restore it on close (`useModal`).

## Brand tone and microcopy voice

- **Voice:** Utilitarian & Minimal
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:**
  - Use engineering terms the way a logic course uses them: tick, net,
    radix, high, low, floating (Z), unknown (X), conflict.
  - Buttons are verb-first ("Add switch", "Delete circuit").
  - Errors say what happened and what to do next, and never blame the
    user.
  - No exclamation marks, no jokes in errors, no marketing tone.

## Icon library

- **Library:** Project SVG
- **Package / path:** `src/ui/icons.tsx`
- **Notes:**
  - 18×18 viewBox, 1.5 stroke, `currentColor`, round caps and joins,
    `aria-hidden`.
  - New icons follow the same grid and stroke.
  - Do not add an icon package.
  - An icon-only button needs a tooltip and an `aria-label`.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task:
   - New page → `page-patterns` (name the pattern before markup).
   - Layout and chrome → `viewports`.
   - Forms → `forms`.
   - Overlays → `surfaces`.
   - Loaders → `loaders`.
   - Empty views → `empty-states`.
   - Motion → `motion`.

   Before finishing UI, run `ux-audit`.
3. Use only the project SVG icons in `src/ui/icons.tsx`. Do not mix icon
   sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog that
   names the thing being destroyed.
6. The canvas is drawn by `src/editor/render.ts`, not by CSS. Visual rules
   here apply to the chrome. On the canvas, the identity colors above and
   the value styles in `valueStyle.ts` rule.
